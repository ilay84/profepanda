# Matching (Left/Right Pairs) – Blueprint

## Schema
- Root: `{ type: 'matching', slug, version, title_es, title_en, instructions_es, instructions_en, level, taxonomy_paths, status, media?: Media[], items: Item[] }`
- Media (optional, root-level, reused across items): `{ id, kind: image|audio|video, src, thumb?, alt_es?, alt_en?, transcript_es?, transcript_en? }`
- Item: `{ id, order, left, right, hint_es?, hint_en?, feedback_correct_es?, feedback_correct_en?, feedback_incorrect_es?, feedback_incorrect_en? }`
  - `left`: neutral string shown in the left column (locked)
  - `right`: neutral string shown in the right column (shuffled bank)
  - Future: allow optional distractors (`distractors?: string[]`) if needed.
- Bilingual: all user-facing hint/feedback fields must provide `_es` and `_en`; core pair text stays language-neutral unless we add dual-language support later.
- Validation: items[] length ≥ 1; each item needs id/order/left/right; no duplicate ids; media URLs validated; taxonomy_paths present if publishing.

## Builder (Admin)
- Base fields: slug (auto-slug from first title until edited), title_es/en, instructions_es/en, level, taxonomy_paths, status (Draft/Published/Archived), JSON editor button, Save/Preview/Publish.
- Items UI: table or accordion of pairs: inputs for `left` and `right`; order sortable; add/remove rows; optional hint/feedback fields per pair.
- Media: optional root-level media[] upload (reuse shared media panel).
- Autoslug: lowercased/kebab-case; stop auto-updating when slug input changes or in edit mode.
- Preview: feeds current payload to runtime via PPX preview bridge.

## Runtime (Player)
- Layout: left column lists `left` strings in order; right column shows shuffled `right` options as draggable/clickable pills.
- Interaction: support drag-and-drop and click-to-select pairing; one-to-one matching (each right used once).
- Check flow: Check enabled once all pairs are matched. On submit, highlight correct/incorrect pairs and show per-pair feedback if provided. Lock inputs after check.
- Summary: when idx === items.length, show summary slide with total correct/total pairs and per-pair results. No media toggle on summary.
- Reset: header reset uses `resetExercise` to clear localStorage/session caches and reopen slide 1 without closing the modal; summary restart reuses the same routine.
- Media toggle: only rendered if media nodes exist in DOM; suppressed on summary.
- Accessibility: aria-label each left/right option; keyboard navigation for selecting matches; live region for check results; focus first error on failed check.

## Analytics
- Increment `api.answer` per pair; `api.complete` on summary. Track hints_used when a hint is first opened for a pair.

## API Endpoints
- GET `/admin/api/exercises/matching/:slug?version=current`
- POST `/admin/api/exercises`
- PUT `/admin/api/exercises/matching/:slug`
- PATCH `/admin/api/exercises/matching/:slug/status`
- POST `/admin/api/exercises/matching/:slug/publish`
